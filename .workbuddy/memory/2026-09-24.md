## 补充：用户说明「Mac 也有内网穿透可以开」

已把迁移指南的配置章节改写为「按穿透情况分两种」。**核心结论不变**：

**`API_BASE_URL` 恒为 `http://api:8000`，Mac 有穿透也只改 `VITE_WS_ORIGIN`。**
理由：`API_BASE_URL` 是 **SSR 侧**（容器内）的服务端请求，走内网即可；
指向公网只会引入隧道依赖 —— 2026-09-21 隧道断掉导致本地界面打不开、
还伪装成"数据初始化失败"就是这个原因。

### 需要两条隧道（不是一条）

| 用途 | Mac 本地端口 | 不开的后果 |
|---|---|---|
| 界面 | `3000` | 外网打不开 UI |
| 后端 API | `18000` | **回测卡在"运行中"**（浏览器连不上进度推送的 WebSocket）|

`101.42.40.10:10004` 若仍被 Windows 占用，Mac 需换远程端口（如 10005/10006），
否则 frps 上撞端口。**两台机器同时跑必须错开。**

### 已核查：换公网地址无需额外放行

- 后端**完全没有 CORS 配置**（无来源白名单）
- WS 端点 `@router.websocket('/backtest/{run_id}/ws')` 直接 `websocket.accept()`，
  **不校验 Origin**
- 前端 Nitro 未设 `allowedHosts`，不会拒绝未知 Host
- **WS 地址来源**：`web/app/config/api.ts` 里 `WS_BASE = import.meta.env.VITE_WS_ORIGIN`，
  未注入时回落同源 —— 而 Nuxt 容器不提供 WS 端点（代码注释已说明），
  故该值**必须**填对，否则回测页面永远停在"运行中"。

## 顺带发现：Windows 侧界面目前打不开（隧道断了）

实测：
- `101.42.40.10:10004/api/v1/system/status` → **HTTP 503**（隧道后端未连接）
- 本机无任何 frp 进程（`tasklist` 匹配 0）
- **`localhost:3000` 请求全部挂住超时**（curl HTTP 000，无响应）
- 后端直连 `localhost:18000/health` → 200 正常

**原因**：Windows 这套的 `API_BASE_URL` 指向隧道，隧道 503 时 Nitro 代理
一直等待 → 整个前端不可用（比报错更糟，表现为无响应）。

**这正是"SSR 侧不该走公网"的实证。** 用户已知情并选择走隧道，未擅自改回。
若用户想让 Windows 界面恢复可用，两个办法：把 frpc 起回来，
或把第 91、94 行改成 `http://api:8000` 再 rebuild。

## ⚠️ 重要纠正：compose 有「工作副本 / 已提交版」两个版本，行数差 50

用户反馈「docker-compose.yml 原文件只有 66 行」。实测：

| 版本 | 行数 | 状态 |
|---|---|---|
| **工作副本** | **111 行** | 已修好的可用版本 |
| **已提交 (HEAD) / GitHub** | **66 行** | **原始仓库的破损版本，起不来** |

`git diff --stat`：**50 insertions, 5 deletions**，且**差异不只是注释**。

### 已提交版（66 行）的 5 处致命错误

1. 第 1 行**无 `name:`** → compose 项目名取目录名 `docker` → 卷命名空间可能撞车
2. **`db.cap_drop: ALL`（第 19 行）** → postgres 启动时 chmod/setuid 被剥夺、**容器立即退出**
3. **api 段完全没有 `ports:`** → 宿主机访问不到 18000
4. **api healthcheck 用 `curl`（第 35 行）** → `python:3.14-slim` 不含 curl
   → **healthcheck 恒失败 → api 永不 healthy → nuxt 永不启动**
5. **无任何 `tmpfs`** → `read_only: true` 下 /tmp 不可写，报只读文件系统

这些都是工作副本里早已修好的。

### 教训 / 给后续的指引

- **报行号时必须声明是哪个版本** —— 否则用户对不上。
  给 Mac 的指引已改为**按内容定位**（找 `nuxt:` → `build:` → `args:`），不依赖行号。
- 已提交版**没有 `args:` 段**，而 `environment.API_BASE_URL` 本来就是 `http://api:8000`
  —— 若用 66 行版，地址无需改，但**必须先修好上面 5 处才能启动**。
- **这坐实了「必须迁移工作副本、不能 clone」** —— 不只是缺功能，是根本起不来。
