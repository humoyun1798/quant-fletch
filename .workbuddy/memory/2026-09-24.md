# 2026-09-24

## 用户需求：把项目跑在 Mac mini M4 上

产出：`tools/qf_mac_migration_guide.md`（完整迁移步骤）。

### ⚠️ 最重要的发现：远端仓库是旧版本，不能直接 clone

实测 `git status`：**38 项未提交改动 + 6 个未跟踪新文件**，
且本地 `main` 与 `origin/main` **领先 0 个提交** —— 即 GitHub 上的代码
**完全不含本轮所有修复**。

未跟踪的关键文件（clone 会全丢）：
- `api/src/strategies/ma10_trend.py` → **MA10 策略整个不存在**（只剩 6 个策略）
- `api/src/data/price_adjust.py` → 断层不修复
- `web/app/config/labels.ts` → 前端中文文案层缺失，构建可能直接失败
- `tools/` → 全部诊断脚本

**所以迁移必须先 `git add -A && git commit && git push`，或直接拷贝目录。**
（`git add -A` 不能省，否则 6 个新文件不会被纳入。）

### 架构兼容性核查（逐项实测，结论：无障碍）

| 项 | 结果 |
|---|---|
| `python:3.14-slim` / `node:22-alpine` / `pgvector/pgvector:pg16` | 均多架构含 arm64 |
| `api/uv.lock` | 含 **109 条 aarch64** 条目 |
| `pnpm-lock.yaml` 原生包 | rollup / esbuild / lightningcss 的 linux-arm64 **都在** |
| `sharp` | 非依赖（0 处引用）|
| `.dockerignore` | 已排除 node_modules/.venv/*.duckdb → `COPY . .` 不带入 Windows 二进制 |
| Dockerfile / compose 行尾 | **全部 LF**，无 CRLF 问题 |
| shell 脚本 | 项目内无 `.sh` |
| `requires-python` | `>=3.14`，与基础镜像一致 |

### 迁移时必须改的配置

`docker/docker-compose.yml` 的 `nuxt.build.args`（含 `environment`）当前指向
**Windows 机器的 frp 隧道** `101.42.40.10:10004`，Mac 上必须改回：
`API_BASE_URL: http://api:8000`、`VITE_WS_ORIGIN: ws://localhost:18000`。

`.env` 被 `.gitignore` 忽略（第 35 行），clone 不会带，需在 Mac 上重建
（键：`DB_PASSWORD` / `AKSHARE_TIMEOUT` / `AKSHARE_RETRY_DELAY` / `BACKTEST_MAX_DAYS`）。

### 其它

- 端口 `18000:8000` / `3000:3000` 在 macOS 上无需修改
  （18000 当初是为绕开 **Windows** 保留端口 7948-8047 才选的）。
- **不要 `docker save` 拷镜像** —— amd64 镜像在 M4 上走 Rosetta，慢且易错，必须在 Mac 上重新 build。
- 新机器数据卷是空的，**必须重新 seed**（约 10 分钟）。
- 建议给 Docker Desktop ≥ 8GB 内存（回测数据量大）。
- 项目只用命名卷、不 bind mount 源码，不受 macOS 文件共享慢的影响。
